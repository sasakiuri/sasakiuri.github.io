# ADR-0002: 静的 HTML の CSP にスクリプトのハッシュを指定する

- 状態: 採用
- 日付: 2026-08-25

## 背景

GitHub
Pages では、リクエストごとに nonce を生成したり、このリポジトリから CSP のレスポンスヘッダーを設定したりできません。Next.js は React
Server Components のデータをインラインスクリプトに出力するため、`script-src 'self'` だけではページが動きません。

## 決定

ビルド後に各ページの HTML を走査し、インラインスクリプトの SHA-256 を計算します。文字コード指定の直後に CSP の `meta`
要素を挿入し、同じオリジンの JavaScript ファイルと、計算したハッシュに一致するスクリプトを許可します。スクリプトに
`unsafe-inline` と `unsafe-eval` は許可しません。

Service
Worker のファイル一覧とキャッシュのバージョンは、CSP 挿入後の HTML から生成します。成果物の検査では、すべてのインラインスクリプトが CSP に記載され、実行するファイルが同じオリジンに存在することを確認します。Playwright でも CSP 違反とコンソールエラーがないことを検査します。

## 効果と制約

- 静的配信と CDN のキャッシュを使いながら、ハッシュを登録していないインラインスクリプトの実行を拒否できます。
- Next.js の出力形式が変わり、検証できなくなった場合はビルドを中止します。
- `meta` で設定できない `frame-ancestors` などは、ここでは制御できません。
- Next.js のインラインスタイルを使うため、スタイルには `unsafe-inline` を許可します。
- 実行するファイルは同じオリジンに限定します。HTTPS の設定は配信先で行い、公開後の監視でも確認します。
- ローカルの HTTP でも同じ成果物をテストできるよう、`upgrade-insecure-requests` は指定しません。
